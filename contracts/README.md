# mzShop 项目契约（入口）

> 每次新开对话先读本文件，再按任务读对应契约。契约与代码冲突时，先向负责人确认，不要擅自二选一。

## 1. 项目概览

- 目的：电商统一数据管理与分析（多平台店铺、商品、订单等数据的汇总、管理、分析）
- 语言：Python 3；数据库：MySQL 8（`pdc_shop`，utf8mb4 / utf8mb4_unicode_ci）
- 连接信息只放各模块 `.env`（已 gitignore），**禁止写进代码、契约、提交记录或聊天**；模板见 `admin/.env.example`

## 2. 目录与模块

| 目录 | 用途 | 状态 |
|---|---|---|
| `contracts/` | 公共契约（本目录） | 进行中 |
| `admin/` | 管理后台：FastAPI + Jinja2 + jQuery + DevExtreme 24.1.3 | 框架已生成：登录、用户管理、Grid/Form 样式配置 |
| `tool/crawler/` | 数据采集工具 | 设计中，见 CRAWLER.md |

## 4. 新任务工作流

1. 读本文件 + 与任务相关的契约；
2. 先说明方案（涉及表结构变更须按 DB.md 提供用途、影响、预览、执行、回滚 SQL，**由人工审核执行**）；
3. 改动遵循现有代码风格，不引入新框架/依赖，除非契约已允许或已确认；
4. 完成后同步更新相关契约（TABLES.md / API.md / ADMIN.md 菜单等）；
5. 新发现的偏差、风险记入 TODO.md。

## 5. 通用约定

- 注释、界面文案、Comment 用中文；标识符（表、字段、变量、路径）用英文。
- 密码用 scrypt 哈希；敏感信息不入普通业务字段、不进日志。
- 不确定的业务规则先问，不按名称猜测。
